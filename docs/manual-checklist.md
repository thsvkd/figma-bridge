# 수동 검증표

자동 테스트로 확인할 수 없는 항목이다. 실제 피그마와 실제 창이 필요하다.

## 화면

`npm run dev` 또는 설치한 앱에서 확인한다. 상태는 가짜 값이 아니라 실제 동작으로 바꾼다.

- [ ] 처음 실행하면 첫 화면 맨 위에 상태 줄과 큰 "연동" 버튼이 한눈에 보인다(스크롤 없이).
- [ ] 꺼짐 상태: 회색 점, "꺼져 있습니다", 버튼 "연동".
- [ ] 연동을 누르면 버튼이 "연동 중…"으로 바뀌고 비활성이 되며, 끝나면 사라지지 않고 결과 상태로 바뀐다.
- [ ] 중계 켜짐, 플러그인 미연결 상태: 주황색 카드, "중계는 켜졌지만 아직 연결되지 않았습니다", 같은 자리에 "플러그인 연결" 버튼이 보인다. 꺼짐과 연결됨 상태와 색이 확연히 다르다.
- [ ] 피그마가 꺼져 있을 때 위 상태의 안내 문구가 "피그마를 켜고 플러그인을 연결합니다"로 바뀐다. 피그마가 설치되지 않았으면 설치 안내가 나온다.
- [ ] 연결됨 상태: 초록색 카드, "연결됨", 버튼 "끄기".
- [ ] 피그마에서 디자인 파일을 닫으면 1~2초 안에 화면이 "플러그인 미연결"로 돌아가고, 다시 열고 플러그인이 붙으면 "연결됨"이 된다.
- [ ] 3055 포트를 다른 프로그램이 쓰고 있을 때 연동을 누르면 원인이 한국어로 카드 아래에 보이고, 상태는 꺼짐으로 남는다.
- [ ] 라이트 모드와 다크 모드 모두에서 글자와 카드 색이 읽힌다.
- [ ] 창 크기를 최소(420x480)까지 줄여도 가로 스크롤이 생기지 않는다.
- [ ] 창의 X를 누르면 앱이 종료되지 않고 숨겨지며, 트레이 아이콘을 누르면 같은 창이 다시 열린다.
- [ ] 트레이 아이콘 색과 툴팁이 세 상태(회색 꺼짐, 주황 플러그인 미연결, 초록 연결됨)를 따른다. 상태가 바뀔 때 시스템 알림은 뜨지 않는다.
- [ ] 트레이 메뉴: 상태 줄, 켜기/끄기, 창 열기, 종료가 있고 "플러그인 연결"은 플러그인 미연결 상태에서만 보인다. 종료를 누르면 프로세스가 사라진다.
- [ ] 설정을 펼칠 때 업데이트 상태가 다시 읽힌다(창이 숨겨진 사이에 새 버전이 나왔으면 알림 줄이 보인다).
- [ ] 설정의 "Windows 로그인 시 자동 시작"을 켜고 로그아웃/로그인하면 창 없이 트레이로만 시작하고, 피그마가 실행되지 않으며 "플러그인 미연결" 상태로 보인다. 끄면 작업 관리자의 시작 프로그램에서 항목이 사라진다.
- [ ] "점검"은 항목별 정상/확인 필요/문제를 보여 주고, "고치기"는 적용한 조치를 목록 맨 위에 보여 준다.
- [ ] "AI 점검"은 진행 중 문구를 보여 주고 끝나면 출력과 점검 결과를 보여 준다. AI 도구가 없으면 한국어 오류가 보인다.
- [ ] AI 도구 설치 목록에서 미설치 도구의 "설치"가 진행 문구와 결과 안내를 보여 주고, 설치된 도구의 "로그인"이 콘솔 창을 연다.
- [ ] 앱이 실행 중일 때 `"<앱 exe>" --status`를 파이프로 실행하면 `relay`가 채워진 JSON이 나온다. 앱이 꺼져 있으면 `relay`가 `null`이다.
- [ ] 앱이 꺼져 있을 때 `"<앱 exe>" --doctor-fix`를 실행하면 앱이 창 없이 시작되어 중계가 켜지고, 피그마는 실행되지 않는다.

## 피그마 조작 (Win32 스모크)

피그마 창이 실제로 앞으로 나오고 키 입력이 들어가는지 확인한다. 대기 시간은 이 결과로 `src/main/figma/timings.ts`를 다시 정한다.

- [ ] 피그마가 실행 중이고 창이 최소화되어 있을 때 연동을 누르면 창이 앞으로 나오고, 퀵 액션(Ctrl+/)으로 플러그인이 실행되며, 끝나면 연동을 누르기 전에 보던 창으로 포커스가 돌아간다.
- [ ] 피그마가 꺼져 있을 때 연동을 누르면 피그마가 실행되고, 창이 나타날 때까지 기다린 뒤 플러그인을 붙인다.
- [ ] 퀵 액션으로 붙지 않으면 마지막 플러그인 재실행(Ctrl+Alt+P)으로 붙는다.
- [ ] 연동을 누른 뒤 피그마가 포커스를 잃으면 키 입력을 멈추고, 원인이 한국어로 보인다.

## 플러그인 설치 여부별 연동

- [ ] **플러그인 설치됨**: 연동을 연속으로 두 번 누르면, 두 번째에는 창이 움직이지 않고 키 입력이 나가지 않는다.
- [ ] **플러그인 미설치**: 연동을 누르면 설치 페이지가 피그마 앱 안에서 열린다. Run을 누른 뒤 연동을 다시 누르면 플러그인이 붙는다.
- [ ] 연동을 연타하거나 더블클릭해도 키 입력은 한 번만 나간다.
- [ ] 끄기와 켜기를 반복해도 MCP 항목은 하나만 남고(`claude mcp list`에서 TalkToFigma가 한 번), 중계 서버도 하나만 뜬다.

- [ ] 스마트 앱 컨트롤을 끈 PC 또는 CI 러너에서 `node script/smoke-packaged.mjs` 를 실행해 패키징한 앱이 뜨는지 확인한다. 서명하지 않은 앱은 스마트 앱 컨트롤이 켜져 있으면 실행 자체가 막히므로, 켜진 PC 에서는 이 검증을 할 수 없다.

## 복원과 자동 시작

- [ ] 연결된 상태에서 앱을 종료했다가 다시 켜면, 피그마가 실행되지 않고 창이 앞으로 나오지 않으며 키 입력도 없다. 중계는 켜지고 상태는 "플러그인 미연결"로 보인다.
- [ ] 로그인 자동 시작을 켜고 Windows에 로그인하면 창 없이 트레이로만 시작한다. 피그마가 실행되지 않는다.

## 업데이트

업데이트 경로는 실제 GitHub Release 두 개(이전 버전, 새 버전)로 확인한다.

- [ ] 이전 버전을 설치한 뒤 새 `v*` 태그 릴리스를 올리면 시작할 때 알림이 뜨고, 다운로드는 사용자가 누를 때만 시작된다.
- [ ] 다운로드가 끝난 뒤 "재시작 후 설치"를 누르면 설치되고, 재시작 후 스위치가 켜져 있으면 중계만 복원되며 피그마는 실행되지 않는다.
- [ ] 오프라인에서 앱을 켜면 앱과 연동이 막히지 않고, 업데이트 상태가 오류로 보이며 "업데이트 확인"으로 다시 확인할 수 있다.
- [ ] **Claude Code가 앱 exe를 MCP 자식 프로세스로 실행 중일 때** 업데이트 설치가 되는지 확인한다. 설치 프로그램이 그 프로세스를 종료하는지 여기에 기록한다. 막히면 MCP 실행용 exe 복사본 방식으로 바꾸는 후속 작업을 따로 만든다.

## 제거와 이전 버전

- [ ] 제거하면 Claude Code(`claude mcp list`), Claude Desktop 설정, Codex 설정(`config.toml`)에서 TalkToFigma 항목이 모두 사라진다. Codex는 `codex mcp add`로 직접 등록한 항목도 포함한다.
- [ ] 제거 화면에서 데이터 삭제를 "아니오"로 고르면 `%LOCALAPPDATA%\FigmaBridge`가 남고, "예"로 고르면 사라진다.
- [ ] 구 PowerShell 버전의 Bun 중계 프로세스가 3055를 잡고 있을 때, 그 프로세스가 `/status`와 `socket.pid`로 확인되지 않으면 설치판의 연동은 포트 점유 안내를 보여 준다. 그 프로세스를 끈 뒤 다시 누르면 켜진다.
- [ ] 구 중계 프로세스는 `/status`가 피그마 연결 릴레이이고 `socket.pid`가 그 프로세스를 가리킬 때만 자동으로 멈춘다(확인되면 안내 없이 켜진다).
